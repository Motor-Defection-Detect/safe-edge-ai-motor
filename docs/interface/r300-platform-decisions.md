# R300 platform parameter decisions

These are engineering defaults, not measured hardware results. Each value remains a
calibration or configuration boundary for board bring-up.

| Parameter | Baseline | Rationale |
| --- | --- | --- |
| STM32 clock | 96 MHz from internal 16 MHz HSI (PLLM=16, PLLN=192, PLLP=2, PLLQ=4) | Avoids dependence on an undocumented BlackPill crystal while remaining below the STM32F411 100 MHz maximum. APB1 is 48 MHz and TIM4 receives 96 MHz. |
| STM32 monotonic clocks | TIM2 at 1 MHz for sensor timestamps; SysTick at 1 kHz increments a 32-bit supervision counter | TIM2's prescaler is latched with an update event before counting. TIM2 naturally wraps after about 71.6 minutes and is used only with microsecond modulo arithmetic; the one-instruction SysTick handler gives millisecond services their expected 49.7-day modulo period, avoiding a false keepalive timeout at the TIM2 wrap. |
| GY-521 / MPU-6050 | I2C2 at 400 kHz, DLPF_CFG=0, SMPLRT_DIV=7 for 1000 Hz, +/-16 g; display default 1/2048 g/count | The 8 kHz internal sample clock is divided by eight so data-ready matches the accelerometer's 1 kHz output limit instead of repeating samples. PB10/PB11 use AF4 and PB1 captures data-ready. `vibration_g_per_count` remains adjustable per axis. |
| Motor PWM | 1 kHz, 3.3 V active-high, forward only, 0% at boot | The selected LR7843 module accepts the STM32 level. It remains a low-side switch rather than an H-bridge, so PB7 stays low and thermal behavior requires bring-up measurement. |
| Motor command | 18-byte CRC frame every 100 ms; 300 ms timeout; 0-1000 permille; STOP/FORWARD only | Resolves SFD TBD-002 without claiming reverse wiring that the v4 pin map excludes. Three missed refreshes force PWM to zero, and a valid Jetson HEALTH plus local acquisition health are also required. |
| Current conversion | ACS712-05B, 5 A, 185 mV/A, 5 V supply, 12k/22k output divider into a 3.3 V 12-bit ADC | `mA = (raw-zero) * 3300 * 34 * 1000 / (4095 * 22 * 185)`, clamped to +/-5 A. Zero is averaged over 256 motor-off samples. |
| Sensor time alignment | MPU-6050 timestamps own the 1 kHz logical rows; each row samples the latest ADC DMA value | The MPU-6050 and STM32 ADC timer have independent clocks. Latest-value hold aligns the scalar current channel while a separate 100 ms freshness check fails closed on ADC loss. |
| Vibration timestamp ownership | TIM2 at 1 MHz is captured in the short EXTI1 DRDY ISR; I2C remains in the main loop | Prevents main-loop/I2C latency from contaminating block timestamps while keeping blocking bus work out of the ISR. A second pending edge increments the sticky overrun counter. |
| ADC DMA ownership | Main-loop NDTR latest-value polling with 128 ms ring-wrap detection | Intermediate 1 kHz ADC samples may advance while the main loop services I2C or CRC. A complete 128-sample ring overwrite latches the diagnostic fault. |
| Jetson UART RX ownership | DMA1 Stream5, 64-byte circular buffer consumed by NDTR ownership polling | DMA avoids UART overrun while the main loop services I2C; 64 bytes hold both 100 ms HEALTH and MOTOR_COMMAND frames with margin. |
| ATmega128A clock | 16 MHz at 5 V, supplied as `R300_AVR_CPU_HZ` | Common development-board crystal value and the device's rated maximum at 4.5-5.5 V. The macro remains a calibration boundary for the actual board. |
| Relay trigger polarity | Explicit `R300_RELAY_ACTIVE_HIGH`; software-verification baseline `1` | Resolves the software side of ICD TBD-004 without pretending the module has been measured. Both polarity branches preload the inactive PD7 level before enabling the output. The build value and external reset bias must be changed only after approved de-energized bring-up evidence. |
| HEALTH / telemetry stale threshold | 180 ms | One missed 100 ms HEALTH plus 80 ms scheduling/transport margin is tolerated. With the AVR's 500 ms timeout, 20 ms remains for unmeasured relay response; telemetry has its separate 128 ms link-health age. |
| Jetson `LINK_HEALTHY` age | 128 ms | One complete telemetry period may elapse without a validated block; the next HEALTH then clears the bit and STM32 stops PB8/PWM. |
| Local sensor stale / identity check | 100 ms | Both nominal streams run at 1 kHz. MPU-6050 WHO_AM_I is re-read at this cadence so a disconnected sensor cannot remain healthy merely because DRDY floats. |
| Waveform / FFT presentation | Calibrated raw-g waveform; per-axis DC removal plus periodic Hann FFT; X/Y/Z magnitude overlays | The screen definition requires a raw waveform and axis-specific magnitude, and leaves overlay versus tabs open. Three overlays preserve every axis without adding tab state or performing work on the UI thread. |
| Dashboard p95 horizon | Latest 100 inference/UI deliveries | A bounded nearest-rank p95 covers about 16 seconds at the 256-sample hop rate, reacts to runtime changes, and avoids unbounded statistics state. |
| Inference handoff queue | 3 validated telemetry blocks | At 128 ms per block, queue backlog plus four abnormal hops and 30 ms inference is bounded to 1.438 s, inside the 1.5 s warning target. Overflow drops stale backlog and resets discontinuous analysis state. |
| Inference worker liveness | 100 ms in-flight deadline | The runtime target is p95 below 30 ms. A callback still in flight at 100 ms is an application stall, not an abnormal classification; the next HEALTH clears `LINK_HEALTHY` so STM32 PWM/heartbeat supervision fails closed. |
| Qt main-loop liveness | 300 ms without a 100 ms dashboard refresh heartbeat | A bound dashboard that misses three refreshes is treated as an application stall. The serial worker clears `LINK_HEALTHY`; an unbound headless acquisition application is unaffected. |
| Sample-rate horizon | Latest 128 full-block STM32 sequence/timestamp observations | At 7.8125 blocks/s this is about 16.4 s. Source timestamps exclude Jetson/UART scheduling jitter; sequence gaps and uint32 wrap retain the estimate. |
| Evidence artifact layout | One run stem produces event JSONL, metrics JSONL, raw binary, CSV index and metadata JSON | Preserves each validated frame byte-for-byte while keeping searchable events and packet offsets separate. Sensor payloads are not redundantly copied into the event log. Default metadata is explicit rather than fabricated: class `unlabeled`, physical condition/mount `unspecified`, fixture `unassigned`, and zero-based `power_cycle=0`; callers should replace these during experiment setup. |
| Automated data QC | 0.5% gap, +/-1% sample rate, >1% values in any channel at >=95% sensor full scale, or >=1 s frozen channel are flagged | Vibration thresholds use the recorded 1/2048 g/count baseline; current uses the selected ACS712 range. Flagged data is reviewed or recollected rather than silently deleted. |
| STM diagnostic publication | Initial calibrated snapshot, then fixed 84-byte CRC frame every 1 s; stale after 3 s | Publishes the measured ADC zero before the first sensor block, then keeps controller/peripheral counters visible without changing the 1040-byte frame. Two periodic publications may be missed; telemetry retains priority. |
| TELEMETRY status byte | sensor ready, local fault, motor command active, plus fresh AVR diagnostic/armed/tripped/E-stop/heartbeat-timeout bits | Uses all eight version_flags status bits. Current calibration is represented by sensor-ready, leaving enough bits for the read-only safety display while relay authority remains on the AVR. |
| AVR power-on state | DISARMED with RESET cause; heartbeat timeout latches only after ARM | Keeps the relay safely off while the Jetson/STM32 link starts. A deliberate ARM with a healthy heartbeat is required before heartbeat supervision can produce a first-out timeout trip. |
| AVR ARM semantics | Debounced active-low maintained permission; raw release removes relay permission immediately; only a debounced release grants another press cycle | Implements the safety truth table `Relay ON = ARM AND heartbeat healthy AND E-stop inactive AND internal healthy` while preventing a held or bouncing button from auto-rearming when a fault clears. |
| AVR heartbeat reset bias | PE4 internal pull-up, pending INT4 cleared before enable, two timely edges required before ARM | Prevents the heartbeat input from floating while STM32 PB8 is high-impedance during reset. Requiring two edges within the 500 ms timeout prevents the STM32's initial LOW drive from being mistaken for a healthy heartbeat. The 3.3 V push-pull source overrides the weak pull-up during normal operation; a stopped level still times out. |
| AVR live safety display | Reuse AVR diagnostic version bits and STM diagnostic status bits; no frame-size change | The AVR publishes current heartbeat/ARM/E-stop/internal/relay-command flags every 100 ms. STM32 freshness-checks them at 300 ms and snapshots them into its existing 1 Hz diagnostic, satisfying the Safety panel update requirement without consuming the fully allocated telemetry status byte. Latched trip state/cause remains separate, and relay command is not presented as contact feedback. |
| AVR watchdog | 500 ms | The safety main loop has no blocking operation, so 500 ms leaves wide execution margin while bounding an internal firmware stall inside the 700 ms relay-command-off target. The physical relay response and reset bias still require bring-up measurement. |
| STM32 register access | Local CMSIS-style typed register structs, no HAL dependency | Keeps the firmware self-contained while replacing anonymous address/offset writes with named peripheral/register access and compile-time layout checks. Peripheral bit fields still map directly to RM0383. |
